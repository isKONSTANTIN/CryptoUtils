Terminal program for seed generation, encryption, decryption, printable backups and more.

## What Is This Thing Good For?

Have you ever thought that writing a mnemonic phrase (or any other secret) on a piece of paper is not the safest storage? Physical damage, loss or declassification is not excluded.

It would be much better if we could safely divide a secret into several parts and distribute them to friends or relatives. A simple split will not work — if we lose even one part, we would not be able to restore the data completely.

CryptoUtils lets you use [Shamir's secret sharing scheme](#shamirs-secret-sharing) to divide a secret into N parts, any K of which are enough to fully restore it — and it prints each part as a labeled, scannable backup card ready for paper storage.

On top of that, it ships commands for QR/PDF417 code generation and scanning, hex encoding of binary files, RSA/ECDHE-based encryption, and BIP-39 mnemonic seed manipulation.

## Example

Everything below was generated by actually running the tool — see [`example/`](example) for the source files. Every command works both scripted (all arguments on one line) and interactively (answer prompts one at a time); here's `backup` used both ways.

Scripted:

```
$ cat secret.txt
This is a demo secret used only to showcase what a CryptoUtils backup card looks like.
It is not a real password, seed phrase or private key.

$ cryptoutils backup file demo 3 2 secret.txt
Backup created: 3 parts, 2 required to recover
Type: FILE
QR error correction level: Quartile (2/4)
demo_1.png
demo_2.png
demo_3.png

Print sheets:
demo_print_1.png
```

Interactive (launch `cryptoutils` with no arguments to get a prompt, then type a command name and answer its questions):

```
cu> backup
Backup source type?
  file - File (Read the secret from a file on disk)
  text - Text (Type the secret in directly)
  seed - Seed (Split a BIP-39 mnemonic phrase)
[file/text/seed] file
Name for these backup copies? demo
Total number of parts (N)? 3
Parts required to recover (K)? 2
Path to file? secret.txt
Backup created: 3 parts, 2 required to recover
Type: FILE
QR error correction level: Quartile (2/4)
demo_1.png
demo_2.png
demo_3.png

Print sheets:
demo_print_1.png
```

Either way, `backup` splits `secret.txt` into 3 shares (any 2 of which reconstruct it) and renders each one as a printable card: a QR code of the share, its hex dump, and a SHA-256 checksum with a CODE128 barcode so a share can be verified without scanning the QR. It also tiles all the cards onto an A4-sized sheet (300 DPI, no rescaling needed) ready to print and cut, saved alongside the cards as `demo_print_1.png`.

Later, any 2 of the 3 shares (scanned back with `qr scan`, or typed in by hand from the hex block) are enough to reconstruct the original file with `restore file`.

## Shamir's Secret Sharing

[Shamir's secret sharing](https://en.wikipedia.org/wiki/Shamir%27s_secret_sharing) splits a secret into `N` shares such that any `K` of them (the *threshold*) reconstruct the original secret exactly, while any `K-1` shares reveal nothing about it at all. That means you can, for example, split a seed phrase into 5 shares handed to 5 different people, requiring only 3 of them to cooperate to recover it — tolerant of up to 2 lost or destroyed shares, without any single holder being able to read the secret alone.

Two commands implement this:

- `shamir` — the raw building block: split any file into N shares (`.shp-*` parts) or join them back, no images involved.
- `backup` — a friendlier wrapper around the same scheme for files, plain text or BIP-39 seed phrases, rendering each share directly as a printable QR backup card (see [Example](#example) above). `restore` reverses it.

## Installation

### Native Binary

CI builds a native executable (via [GraalVM native-image](https://www.graalvm.org/latest/reference-manual/native-image/)) for Linux, x86_64 and arm64 — no JVM installation required to run it. Download it from the "CryptoUtils-native-\*" artifacts on the [latest GitHub Actions run](https://github.com/isKONSTANTIN/CryptoUtils/actions/workflows/gradle.yml). On Windows, use the jar instead (`java -jar CryptoUtils-*.jar`, requires JVM 17+).

To build it yourself, the easiest way is via Docker, which reproduces the same build CI uses:

```
docker buildx build -f docker/native-build.Dockerfile --target export --output type=local,dest=out .
```

The binary is written to `out/cryptoutils`.

Alternatively, without Docker, install a [GraalVM](https://www.graalvm.org/downloads/) JDK (25 or newer) and run:

```
./gradlew nativeCompile
```

The binary is written to `build/native/nativeCompile/cryptoutils`.

### .deb / .rpm Packages

CI also builds `.deb` and `.rpm` packages (installing the native binary to `/usr/bin/cryptoutils`) for x86_64 and arm64 — download them from the "CryptoUtils-deb-\*" / "CryptoUtils-rpm-\*" artifacts on the [latest GitHub Actions run](https://github.com/isKONSTANTIN/CryptoUtils/actions/workflows/gradle.yml).

To build them yourself via Docker:

```
docker buildx build -f docker/native-build.Dockerfile --target package-export \
    --build-arg VERSION=1.0.0 --build-arg PKG_ARCH=amd64 \
    --output type=local,dest=out .
```

`PKG_ARCH` is the Debian architecture name (`amd64` or `arm64`) — the `.rpm`'s architecture (`x86_64`/`aarch64`) is derived from it automatically. The packages are written to `out/`.

### Plain Jar

```
./gradlew build
java -jar build/libs/CryptoUtils-*.jar
```

Requires a JVM 17+ (any platform).

## Commands

Every command works both interactively (run it with no arguments inside the `cryptoutils` prompt and it will ask questions one at a time) and scripted (pass all arguments inline, e.g. `cryptoutils shamir split 3 2 secret.txt`).

### Backups

| Command | Description | Arguments |
|---|---|---|
| `backup` | Split a file, text or seed phrase into Shamir shares and print each as a labeled QR code | `file\|text\|seed <name> <all_parts> <parts_for_recover> <source...>` |
| `restore` | Reconstruct a file, text or seed phrase from Shamir shares recovered from QR codes or manually entered hex | `file <output_path> <chunk_1\|null> ... \| text <chunk_1\|null> ... \| seed <chunk_1\|null> ...` |
| `qr` | Scan a QR code image to recover its content, or generate a new code image from text or a file | `scan <image path> [result path] \| generate <result path> <pixels width> [error correction level] <source text/f:path>` |
| `pdf417` | Same as `qr`, but using the PDF417 barcode format | `scan <image path> [result path] \| generate <result path> <pixels width> [error correction level] <source text/f:path>` |
| `hex` | Convert files to and from a simple hex text representation | `<encode/decode> <source path> <result path>` |

### Cryptography

| Command | Description | Arguments |
|---|---|---|
| `shamir` | Shamir's secret sharing algorithm: split a file into N parts so that any K of them can reconstruct it, or join parts back into the original file | `split <all parts> <parts for recover> <path> \| join <result path> <part 1 \| null> <part 2 \| null> <part 3 \| null> ...` |
| `rsa_key` | Generate an RSA key pair for encrypting/decrypting seed entropy | `<public RSA key file path> <private RSA key file path> [keys size]` |
| `ecdhe_key` | Generate an ECDHE key pair for deriving a shared AES-GCM secret with another party | `<public ECDHE key file path> <private ECDHE key file path>` |

### Cryptocurrencies

| Command | Description | Arguments |
|---|---|---|
| `seed` | Generate a fresh random 12/24-word seed phrase, or restore one from base64-encoded entropy | `[base64 string]` |
| `seed_to_base` | Transform a seed phrase into its raw base64 entropy (without the checksum word) | `<word_1> <word_2> ...` |
| `seed_to_hex` | Transform a seed phrase into its raw hex entropy (without the checksum word) | `<word_1> <word_2> ...` |
| `hex_to_seed` | Restore a 12/24-word seed phrase from raw hex entropy | `<hex string>` |
| `extend_seed` | Extend a 12-word seed phrase to a 24-word one by putting a checksum hash into the entropy | `<word_1> <word_2> ...` |
| `wordlist` | List available BIP-39 wordlists or change the active one used to build/check seed phrases | `list \| set <name>` |
| `seed_rsa_cipher` | Encrypt or decrypt seed entropy using an RSA key pair | `<encrypt/decrypt/decrypt_old> <base64 original/encrypted RSA entropy> <public/private RSA key path>` |
| `seed_ecdhe_cipher` | Encrypt or decrypt seed entropy using an ECDHE shared secret derived from two key pairs | `<encrypt/decrypt> <public ECDHE key path> <private ECDHE key path> <base64 original/encrypted ECDHE entropy>` |

### Misc

| Command | Description | Arguments |
|---|---|---|
| `help` | Show list of commands | `[command]` |
| `cd` | Change current directory | — |
| `delete` | Overwrite a file with zeros and delete it | `<file>` |
| `exit` / `q` | Exit from CryptoUtils | — |
